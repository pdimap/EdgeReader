# Проверка EdgeReader 2.0.1

Статус: кандидат на проверку, НЕ готовая принятая версия по ТЗ.

## Выполнено в Linux
- 9 модульных тестов: пройдены. Windows API и аудиобиблиотеки в этих тестах заменены заглушками.
- Проверка синтаксиса Python и git diff --check: пройдены.

## Изменения
- Фиксируется HWND при горячей клавише; смена окна отменяет извлечение.
- Последовательное извлечение, идентификатор запроса отбрасывает устаревшую озвучку.
- Автокопирование ждёт отпускания модификаторов и свежего номера Clipboard, проверяет процесс владельца.
- Буфер восстанавливается только при неизменном номере последовательности под блокировкой Clipboard; сохраняются все поддерживаемые простые форматы.
- Сложные форматы НЕ перезаписываются. Полная поддержка OLE/IDataObject ещё не реализована. При недоступности UIA чтение такого выделения будет отказано.
- Отмена сетевого запроса опрашивается каждые 100 мс; сетевой таймаут 60 с; потоки вывода сериализованы.
- Тест звука, диагностика выделения без показа текста, настройки голоса/скорости.
- Inno Setup: установка на пользователя, удаление, неподписанный EXE и SHA256.

## НЕ ПРОВЕРЕНО — обязательная приёмка
Все следующие сценарии требуют настоящей интерактивной Windows 10:
Блокнот; Chrome (страница и textarea); Word; Edge PDF; Adobe PDF; скан PDF; отсутствие выделения; сохранность изображения/HTML/RTF/файлов; реальная пауза/остановка; нет интернета; повторное чтение; слышимый звук.
Записывать версию Windows и приложения, способ получения выделения, результат и слышимость звука без пользовательского текста.

GitHub Actions проверяет сборку, установку и запуск, но не слышимый звук. CI Windows Server не заменяет проверку на чистой Windows 10 без Python.

## Оставшиеся ограничения
- Нет трея, редактора горячих клавиш, выбора аудиоустройства и offline TTS.
- UIA провайдер сторонней программы может зависнуть; отдельный процесс с таймаутом ещё нужен.
- Внешнее изменение Clipboard в том же процессе-источнике нельзя однозначно отличить от Ctrl+C; это ограничение Windows Clipboard. Не выполнять другие копирования во время извлечения.
- Автоопределение языка эвристическое.
- Поддержка конкретных Word/PDF адаптеров требует проверки.

## Обновление 2.0.2: ручное копирование
По запросу пользователя автоматическое извлечение заменено чтением буфера: Ctrl+C → Ctrl+Alt+X. Ранее описанные ограничения UIA и CLIPBOARD_PROTECTED больше не относятся к рабочему пути приложения. Модуль selection.py оставлен как неиспользуемый старый код.
Добавлены 6 модульных тестов чтения буфера и 2 Windows-интеграционных теста: Unicode+HTML без изменения данных и глобальная горячая клавиша → буфер → вызов Speaker. Последний тест подменяет Speaker и не подтверждает звук.
Пользователь подтвердил слышимый тестовый звук предыдущей сборки. Озвучка текста в новой сборке на его ПК ещё не проверена.

Уточнение проверки 2.0.2: системный Clipboard с HTML проверяется без подмены. Тест UI вызывает зарегистрированный callback, подменяя регистрацию клавиш и Speaker. Две попытки синтетического системного ввода в CI не запустили callback; физический Ctrl+Alt+X остаётся НЕ ПРОВЕРЕН. Добавлена кнопка «Прочитать буфер» с тем же рабочим путём.
